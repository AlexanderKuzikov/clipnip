# Безопасность ClipNip

## Ложные срабатывания антивирусов

ClipNip — desktop-загрузчик медиа на Go + WebView2, работающий как оркестратор
yt-dlp: запускает его дочерним процессом и разбирает вывод.

**Срабатывания ложные, вируса нет.** Причина — конструкция, а не поведение:
`clipnip.exe` вшивает три исполняемых файла (yt-dlp, ffmpeg, deno) в виде gzip,
распаковывает их в `%LOCALAPPDATA%\clipnip\bin` при первом запуске и запускает.
Сканер, распаковывающий наш exe, видит PE-внутри-PE и файлы, распакованные во
время работы, — это сигнатура дроппера, на которую эвристики сторонних движков
реагируют по сигнатуре, а не по факту вреда.

Windows Defender с актуальными подписями файл не помечает — проверено локально
через `MpCmdRun -Scan -ScanType 3 -File clipnip.exe`.

Обфускация и упаковка тут не помогают и не нужны: нагрузка легитимная, а такие
приёмы только усиливают подозрение.

### Что можно сделать

**Компоненты с сервера (`-tags clipnipremote`, 7.6 МБ).** Сборка не содержит ни
одного PE, поэтому сигнатуре дроппера не из чего построиться — это убирает
причину срабатываний, а не маскирует симптом. Компоненты берутся с
`https://clipnip.135.106.192.125.nip.io` и проверяются по SHA-256 из манифеста.

Загрузка защищена: только https (без TLS манифест с хешем шёл бы тем же
каналом, что и файл, и сверка не значила бы ничего), атомарная установка —
файл сначала во временное имя, хеш считается на лету, `rename` только при
совпадении. Повреждённая загрузка никогда не становится рабочим бинарником.

Разрешение компонента идёт по порядку: `clipnip-bin` рядом с exe → кэш в
`%LOCALAPPDATA%\clipnip\bin` → сервер. Portable-папка делает поставку
переносимой и полностью офлайн.

**Подпись кода (Authenticode).** Не снимает эвристику про упаковку, но убирает
блокировки, опирающиеся на репутацию и на факт отсутствия подписи.

Чего делать не стоит: упаковщики-крипторы, антианализ и обфускация против
сканеров — это техники из арсенала вредоносного ПО. На легитимной нагрузке они
дают обратный эффект: сигнатура уплотнения становится только заметнее.

## Проверка целостности встроенных компонентов

ClipNip сверяет SHA-256 каждого распакованного бинарника с эталоном, зашитым в
исходный код (`embeddedBins` в `ytdlp.go`). Несовпадение означает подмену файла
в пользовательской папке: ClipNip перераспаковывает компонент из встроенной
копии и **не запускает** подменённый файл.

Эталоны проверяются юнит-тестом: ровно 64 hex-символа, нижний регистр, без
повторов. Обрезанный при копировании хеш — реально случившаяся ошибка: приложение
объявляло исправный файл подменённым и отказывалось стартовать.

Компонент ffmpeg намеренно оставлен без сверки: для него поддерживается ручное
обновление, когда пользователь кладёт свою сборку.

Полная сверка 215 МБ занимает ~1.6 с при старте.

## Известные ограничения

- ClipNip ходит в сеть по маршруту системы. Если доступ к заблокированному сайту
  организован расширением браузера, а не системным VPN, приложение до него не
  дотянется: отдельной настройки прокси нет, это осознанное решение.
- Cookies читаются из профиля браузера только по явному выбору пользователя
  (opt-in, с предупреждением). Значения cookies в приложение не попадают и в лог
  не пишутся.
