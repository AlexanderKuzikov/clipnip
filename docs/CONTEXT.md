## Open-проблемы

| # | Приоритет | Описание |
|---|-----------|----------|
| 1 | low | Скорость по дельте байтов сглаживает всплески и не работает для одиночного тика; при коротких файлах (скачивание быстрее интервала опроса) скорость не покажется вовсе |
| 2 | info | Прямой доступ к YouTube и части сайтов (X, Facebook, xv-ru, Xvideos) закрыт по сети РФ — нужен VPN. ClipNip наследует маршрут системы, отдельной настройки прокси нет (осознанное решение) |
| 3 | info | Invoke-RestMethod падает на loopback в этой среде (прокси) — тестировать через `curl.exe --noproxy "*"` |
| 4 | low | Снятие `--no-playlist` не проверено на реальных страницах X/Facebook/xv-ru с несколькими роликами — URL'ов от пользователя не было. Косвенно проверено, что watch-URL с параметром `list=` остался одиночным видео |
| 5 | low | Часть высот отдаётся как «(alt)» (VP9/AV1 в webm): на той же высоте https-вариант существует только в webm, мерж в mp4 даёт файл, который понимают не все плееры |
| 6 | low | deno (+42 MB gzip) вшит «на всякий случай»: на этой машине подтверждено, что без него JS-рантайма нет вообще, но YouTube и так работал и без него. Если exe начнёт мешать — вынести deno в отдельный релиз-ассет |

| 2026-10-07 | v1.0.0 (фаза 4, надёжность): **счётчики по компонентам** — склейка качает видео и аудио отдельными файлами, и карточка показывала размер последнего компонента (9.8 MB вместо 153.7 MB); сделано накопление `DoneTotal + Cur*`, начало нового компонента определяется откатом байтов (первая попытка «просто суммировать» дала свой баг — Total не выставлялся для первого компонента, прогресс стоял на нуле). **Скорость:** добавлен случай `B/s` в парсер (yt-dlp печатает сырые байты при скорости ниже 1 KiB/s) и расчёт по дельте байтов при `NA`. **Очередь на диске** (`queue.json`): сохраняется состав пачки, не стейт-машина — перезапуск посреди «Download All» больше не требует вставлять всё заново; обновление в трёх точках (defer в runDownload накрывает все терминальные состояния, cancelJob, постановка в очередь); пустая очередь удаляет файл. **Один экземпляр** — именованный mutex (в GUI модалка, в headless только лог: модалка вислала вечно — поймано на первом прогоне). **`.part` TTL 24 ч → 7 дней** — пауза на пару дней больше не убивает докачку. **Лог:** cooldown пишется один раз на смену вместо строки на каждого воркера; потолок retry меряет суммарное ожидание между попытками (`RetryWait`), а не время с первого ретрая (из-за чего джоб с двумя короткими ретраями выглядел как «13m»). **Лог открывается из UI** (`/api/log`: хвост в модалке + открыть файл). **Канал движка переключён на nightly** 2026.09.27 после прогона (идентичный результат) и **ADR 006 переписан**: моё прежнее обоснование отказа от nightly было неверным — ассеты живут месяцами, а после вшивания в gzip их существование не имеет значения; сам README yt-dlp называет stable «склонным к внешним поломкам» и рекомендует nightly. ## Структура проекта

```
D:\GitHub\ClipNip\
├── main.go          # WebView + loopback-сервер (127.0.0.1:0)
├── api.go           # HTTP-контракт (наследник ReClip/app.py)
├── jobs.go          # джобы, адаптивная параллельность, ретраи, очередь
├── ytdlp.go         # yt-dlp subprocess, прогресс, stall-детект, kill-tree
├── config.go        # конфиг (%LOCALAPPDATA%\clipnip\config.json)
├── winutil.go       # WebView2 check, MessageBox, иконка окна, лог
├── embed.go         # //go:embed web embedded
├── web/             # index.html, favicon.svg, fonts/
├── icon/            # clipnip.svg, clipnip.ico
├── rsrc.syso        # ресурсы exe (иконка)
├── docs/            # CONTEXT.md, DECISIONS.md
└── clipnip.exe      # сборка: -s -w -H windowsgui
```
